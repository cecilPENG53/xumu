# 制作路线与合成

## 共用规则

- 只实现已确认、或已授权自主决定的镜头。
- 每个镜头任务写明：shot_id、局部起点帧 0、全片起点、时长、画幅、fps、style、engine、素材、字幕安全区、声音策略、验收帧。时间用 [时间引用](timeline.md#时间引用) 书写，帧数由 `cue.py` 换算。
- 字体文件放进项目；每次改文案后运行 `media_tools.py fontcheck --font <字体> <页面/文案文件>`，有缺字（常见 → ✓ ≈ ≤ 等符号）就改用内联 SVG 或换说法；需要 woff2 子集时加 `--subset`。
- 输出到 `edit/animations/<shot-id>/` 或 `edit/assets/`，依赖装在项目内。外部组件与素材记录来源与许可，商用按各资产的许可处理。
- 全片共用一份只读设计规范：色板、字体文件、字号层级、弹簧档位、避开清单。每个镜头从它取值。
- 渲染遵守 [确定性渲染](style-stack.md#3-渲染引擎)。每个镜头按"静帧 → 短测 → 正式渲染 → 验收"推进，通过后进主片。

## 口播剪辑链

Video Use 负责转录；剪辑点、拼接与时间表由 `voice_edit.py` 完成。这条链在 7 分 41 秒成片中实测，音画误差不超过 1 帧。

1. **保留表 `keeps.json`**：按段落写"从哪句到哪句"，`[开始锚点, 结束锚点, 强制开始秒?, 强制结束秒?]`。锚点是转录原文的片段，同一来源按阅读顺序查找，重复的话也能对上。
2. **生成 EDL**：`voice_edit.py edl keeps.json --out edl_voice.json --report 剪后口播_核对.txt`。默认前留白 0.06 秒、后留白 0.10 秒；段内停顿超过 0.75 秒就拆开，只保留 0.45 秒；剪点按音量移到真实静音处，开头只修第一个音节之前的部分。每段长度对齐到整帧。
3. **核对**：通读 `剪后口播_核对.txt`，抽听剪点。转录把重复起头合进一个词（如"OPC，OPC"）、精修仍剪不干净时，在该条保留项上填强制秒数兜底。
4. **拼接**：`voice_edit.py render edl_voice.json --out build/voice_cut.mp4`。每段按精确帧数和采样数截取、加 30ms 淡入淡出，再用 concat **滤镜**一次编码。concat demuxer 按时间戳拼接，会累计漂移（实测 2.4 秒），不用于这一步。
5. **时间表**：`voice_edit.py cues edl_voice.json --transcripts transcripts --out-dir <edit>` 生成 `cue_chars.json`、`sections.json`，之后的画面时间都用 [时间引用](timeline.md#时间引用)。

修改剪辑时只改 `keeps.json`，按 2 → 5 重跑，再 `cue.py sync`。

## A. 原片与 B-roll 素材

主剪辑在 Video Use 中完成。现成的录屏、截图、实拍可直接插入，需要运镜时交给主合成引擎。检查起止、构图、授权与保密信息。主旁白持续播放，B-roll 自带声音静音；要保留的拟音单独作为 SFX 轨。

- **长录屏切片**：把片段表写进 JSON，用 `media_tools.py clips` 统一裁切、变速、缩放到交付画幅、短关键帧间隔（`-g 15`，合成器才能准确跳帧），同时输出首帧、末帧和抽帧表。首末帧用于衔接（如白板上的显示器画面），抽帧表用来逐段检查画面内容。
- **网络素材**：下载前取得同意并记录来源到 assets.json。用 `media_tools.py cutpoint` 在关键句前后找音量谷值作剪点；用 `media_tools.py level` 把各段统一到相近音量（如平均 -19 dB、峰值 -1.5 dB）后再进合成。

## B. Shotcraft 配方

完成 [Shotcraft 选镜头](shotcraft-direction.md) 的比较、样片检查与全片分镜后，把所选的准确源码与公共组件复制到镜头项目，修正导入、素材路径与依赖版本。保留关键参数，把文案、颜色、目标值、尺寸与布局参数化；字号与色板取自本片设计规范。配方时值与主片不相容时，回到选择记录换卡或修订方案。

## C. 定制 MG

先记录 MG 六问的结论：现有配方表达不了的关系、计算逻辑或专属图解，以及静态呈现不够的原因。按 [风格与技术栈](style-stack.md) 选绘制技术（SVG、Canvas、WebGL、Three.js、p5 等）与引擎实现。数字和文字可精确控制、可修改，数据与来源一致。动手前按 [mg-prompt-patterns.md](mg-prompt-patterns.md) 写 `shots/<shot_id>/brief.md`，并遵守其第 6 节确定性渲染契约：Remotion 用帧号计算一切状态，独立 HTML/Canvas/Three.js 页面暴露 `window.seek(t)` 并用 Playwright 逐帧截图出片，不录屏；重复帧像素一致、乱序帧与顺序帧一致两项检查不通过的镜头不进主片。HyperFrames 效果库条目本身是可逐帧定位的 HTML 合成，用 `hyperframes render` 单独出片（叠加层用 `--format webm` 或 `mov`），同样抽帧验证后再交回主时间线。可与 Shotcraft 运镜分层结合，标清主次。复杂数学推导可用 Manim。

## D. 插画与有限动作

区分静态完整插画与可动资产：独立移动的手臂、头部、道具需要分层或多姿态；纯推近只需完整图。

流程：角色外观、场景、道具一致性约束 → 生成或复用图像 → 审核 → 分层或姿态准备 → 引擎编排运动。图像生成使用当前可用的图像 Skill，并遵守其规则。

不用付费模型时，可用原创 SVG/Canvas 矢量绘制或 p5 手绘笔触制作角色、场景与道具（见 [风格目录](style-catalog.md) 中的 `flat-diagram`、`hand-drawn`、`pixel`、`paper-craft` 等）。先用代表构图确认画风与动作能力；用户要求精细画风时，按要求的精细度实现，或说明所需资源。

## E. 外部视频、人物抠像与 3D

先分清需要的是复杂表演、真人入景，还是可编辑模型。

- **复杂表演**：评估图生视频；模型与版本以当前会话可调用的工具为准。
- **真人入景**：按 [人物抠像进场景](style-stack.md#5-人物抠像进场景)。
- **3D**：风格化场景用 Three.js 代码几何；写实产品用用户提供的模型文件。生成的 MP4 按视频素材处理。

外部生成任务包至少包含：shot_id、timeline revision、目标时长与画幅、主动作、连续性约束、参考文件、正向提示词、需避免的内容、是否需要声音、输出文件约定、验收标准。只上传任务需要的素材。

状态流转：planned → awaiting_approval / waiting_external → rendered → verified。接口可调用、账户可用、上传与费用已获授权后才提交；保留真实 job ID 与费用/次数记录。异步任务按工具的正式轮询机制等待，跨回合时如实说明状态。

接口未接通时，交付任务包，用户生成后回收文件并探测。重试最多 2 次，且受预算约束；仍失败或需要换平台时，停下该镜头，给出换路线或等待的选择。

## 合成

### 有视频底片

先完成主剪辑与调色的底片：逐片段提取后无损拼接，片段边界加短淡入淡出；覆盖层时移后叠加，字幕最后烧录。

本机 Video Use 的 `helpers/render.py` 只读取 `file/start_in_output/duration`，只映射底片音频。同画布、不透明、无声的全屏插入可以走这个接口；Alpha、SFX、画布变换、抠像叠加在项目内写单独的合成脚本。

### 无视频底片（音频/文案模式）

在主合成引擎中按计划组装连续背景镜头，或逐镜头渲染后用 FFmpeg 拼接，再加入锁定的旁白。背景可以是实拍、插画、图解或设计过的色场，从头到尾覆盖全片。当前协议支持硬切与片内入退场；需要镜头重叠的交叉转场时，先扩展时间线协议。

### 透明、声音与字幕

- 覆盖层输出全画布 Alpha 素材，元素位置由画布内部控制；H.264 MP4 不带透明通道。
- Remotion 透明导出按当前官方 render 参考（如 VP9 WebM + yuva420p，或 ProRes 4444）。本机 FFmpeg 读取 VP9 Alpha 时，在该输入前加 `-c:v libvpx-vp9`；正式执行前先做小样。
- 素材的实际尺寸、fps、时长与计划一致。小样检查半透明边缘与首尾帧；用 `setpts=PTS-STARTPTS+T/TB` 让局部第 0 帧落在指定起点，窗口按半开区间处理。
- 主旁白只混一次；SFX 按局部帧偏移单独成轨；BGM 单独控制，旁白出现时压低；生成镜头自带的人声静音。
- 字幕在所有覆盖画面之后烧录（例外：使用 HyperFrames 背后字幕的人物段已自带字幕，按 [后端发现](backends.md#背后字幕的衔接) 的衔接规则处理）。全部混音完成后，先用 `media_tools.py measure <成片> --ranges <开场段>,<正文段>` 分段测响度：来源不同的段（如开场网络素材）与口播差距明显时，先单独调整该段。再用 `media_tools.py normalize` 做两遍归一化（短视频平台常用约 -14 到 -16 LUFS、峰值低于 -1 dBTP，以发布平台规格为准），检查削波。
- Windows 路径含空格、中文或盘符时，用参数数组与 JSON 文件传参；SRT/libass 与 concat 路径做实渲验证。

## HyperFrames

白板一镜到底的完整模板与做法见 [白板一镜到底](whiteboard-world.md)。

以下来自 HyperFrames 0.8.81 整片实测。动手前仍先加载当前会话的 hyperframes Skill，以其规范为准。

**工作流**
- 用项目脚本（Python 等）生成合成工程（`index.html` + 素材），镜头计划写在生成脚本里，时间全部通过 `from cue import Timing` 解析（`sys.path` 加入 `<skill>/scripts`）。
- 项目 `package.json` 锁定版本（如 `npx --yes hyperframes@0.8.81 check` / `render`）。插件自带的 `plugin-cli.mjs` 位于已加载 hyperframes Skill 的 `scripts/` 下，提供 `check`、`snapshot`、`render`；该目录随会话变化，按当次加载路径调用。
- 每次修改：`check` 结构检查 → `snapshot --at <时刻列表>` 截关键时间点 → 确认后再整片 `render`。整片渲染耗时约等于片长（7.6 分钟片约 7 分钟），长片渲染前告知用户。
- 没有"只渲染一段"的参数：出参考片时，让生成脚本把总时长截短（如环境变量 `PREVIEW_END`）。
- 截图时刻至少覆盖：每个世界/场景的切换点、每次衔接前后 0.1 秒、每次人像放大、每段动画的中点。

**坑**
- 每个视频元素必须有 `id`，否则渲染卡住。
- 不要直接对计时片段（clip）做动画，框架会把正在播放的片段强制设为不透明；动画加在外层不计时的容器上。
- 素材关键帧要密（`-g 15` 或 `-g 30`）；关键帧间隔长（如 8 秒）会告警且跳帧不准。
- 用 z-index 明确层级，例如录屏容器 3、贴纸 6、人像 20，全片统一。
- 可以有多个"世界"层，每个配一台虚拟镜头。
- 人像等视频层在对应口播结束时淡出，避免视频结束后留下空容器（如空的灰色圆框）。
- 圆头描边线条在虚线偏移等于全长时会显示成一个点：开始描画前先隐藏线条。

## Workbench

用户需要可视化全片编辑时，读 Shotcraft 的 workbench 参考，实现 `WORKBENCH` 清单、组件 props/schema 与帧级一致性检查。渲染后的 MP4 无法还原为可编辑组件；导入与渲染测试通过后，再称工作台可用。
