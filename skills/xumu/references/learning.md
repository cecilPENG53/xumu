# 学习模式：从案例到手法卡

用户发来剪辑视频、风格案例、教学视频、教程文章或截图，并表示"学一下""收进手法库""总结这个手法"时进入本模式。目标是把案例里**可迁移的做法**归纳成手法卡，以后在匹配的内容上调用。

## 存放

| 内容 | 位置 |
|---|---|
| 待确认的手法卡 | `<skill>/library/inbox/` |
| 已入库的手法卡 | `<skill>/library/cards/` |
| 素材（原视频、抽帧、拼图、转录） | 媒体根目录 `<media_root>/<卡片 ID>/`；由环境变量 `XUMU_LIBRARY_MEDIA` 或 backends.local.json 的 `learning.media_root` 指定 |

手法卡是纯文字，随 Skill 一起保存和迁移；素材留在本机媒体目录，不放进 Skill。学习模式是本 Skill 中唯一会写入 Skill 目录的流程，只写 `library/`。

**入库方式：默认逐张确认**。新卡先写进 `inbox/`，用户确认后再用 `confirm` 移入 `cards/`。用户要求改为自动入库时，在其 `project.md` 或个人配置中记下这项偏好，之后按偏好执行。

## 流程

### 1. 获取

- 链接：用 agent-reach 读取对应平台（X、B站、YouTube、小红书等）的正文、字幕和元数据。
- 需要下载视频时，先告诉用户文件名、来源和大小，取得同意后下载到 `<media_root>/<卡片 ID>/`。
- 本地文件：复制到媒体目录，原文件保持原位。
- 文章、帖子：读全文，包括作者附带的提示词和参数；图片里的文字逐张看。

### 2. 拆解

**视频**：
- `ffprobe` 记录时长、分辨率、帧率。
- 用场景检测找出剪切点，抽帧拼成联络表，看整体结构与节奏。
- 口播内容影响剪辑决策时，转录并对照时间点。
- 以正常速度观看重点段落；快速动作处拼连续 12 帧细看。
- 记录：剪切节奏、转场方式、镜头运动、字幕和花字样式、动效的入场 → 落点 → 停留 → 退出、声音与画面的配合、色彩与字体。

**教程、文章**：提炼方法、参数和作者的结论，区分作者的主张与可验证的事实。

### 3. 提炼成手法卡

- 一个来源可以产出多张卡；每张卡只讲一个可迁移的手法。
- 把手法从原作的具体内容中抽象出来：写"什么样的内容会需要它"，而不是复述原视频讲了什么。
- `triggers` 写成内容特征，例如"前后对比""步骤流程""金句收尾""数据跳变"，以后靠它匹配文案。
- 能落到序幕现有体系时写明对应关系：`style`（[风格目录](style-catalog.md) 的 key）、`engine`、相关 Shotcraft 卡。
- 参数写具体：时长、帧数、缓动或弹簧档位、节拍位置、字号比例、颜色关系。

### 4. 查重

先用 `library_tools.py search` 检索已有手法卡，再看 [风格与技术栈](style-stack.md) 和 Shotcraft 镜头库是否已经覆盖。

- 已有相同手法：在原卡上补充新来源、新参数或新的适用场景，标为"更新"。
- 部分重叠：在新卡里写清与旧卡的区别，并互相链接。
- 已被 Shotcraft 某张卡覆盖：只在手法卡里记录"对应 Shotcraft 卡 X 的用法"，不重复描述动作实现。

### 5. 给用户确认

用简短的列表展示本次结果：每张卡的名称、一句话总结、适用场景、是新增还是更新。用户确认、修改或删除后：

```text
python <skill>/scripts/library_tools.py confirm <卡片 ID>
```

更新已有卡时，同样先展示改动，确认后再写入 `cards/`。

## 卡片格式

用 `library_tools.py new --name "<名称>" --kind <类别>` 生成骨架，再填写：

```markdown
---
id: L0001
name: 光标点击驱动的界面变形
status: draft
kind: motion
triggers: [工具教程, 操作流程, 功能切换]
tags: [界面, 弹簧, 光标, 节拍]
style: clean-ui
engine: [remotion]
shotcraft: []
sources: [https://x.com/..., 作者 @xxx]
media: [L0001/contact.jpg]
created: 2026-10-10
updated: 2026-10-10
---

## 一句话
## 适用 / 不适用
## 为什么有效
## 做法与参数
## 在序幕里怎么实现
## 原案例拆解
## 使用记录
```

`kind` 取值：`structure`（叙事结构）、`edit`（剪辑与节奏）、`motion`（动效与运镜）、`style`（视觉风格）、`type`（字幕与花字）、`sound`（声音）、`workflow`（制作流程与工具技巧）。

## 制作时调用

第 3 步画面方案中，对每个段落：

1. 用段落的内容特征和本片主风格检索：`python <skill>/scripts/library_tools.py search <关键词…>`，只返回已入库的卡。
2. 完整阅读命中的卡，判断是否真的适合这一段：内容特征、时长窗口、主风格、素材条件都满足才用。
3. 选择表"手法卡"一栏写明卡片 ID 和用法；用户能看到哪一条在起作用。用户点名的手法卡按核心原则 3 处理。
4. 个人配置里登记了其他视觉参考库（色彩、构图、运动样本）时，同时以只读方式检索（见 [后端发现](backends.md)）。

交付后，在用到的卡的"使用记录"里追加一行：日期、项目、段落、效果反馈。用户不满意的用法写进"适用 / 不适用"，避免重复踩坑。

## 升级为规则

某张手法卡在多个项目里稳定好用、且适用面很广时，可以提议把它并入 style-stack 或其他参考文件，成为默认规则。提议时说明依据（使用记录），用户确认后再改。

## 来源与版权

手法卡记录的是分析与归纳，用自己的话写，不整段搬运原文。素材副本只用于本机学习，不随 Skill 分发、不上传。原作者在卡片 `sources` 中注明。
