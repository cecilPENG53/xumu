# 定制 MG：灵感检索、需求写法与确定性渲染

只在 [directing.md](directing.md) 的 MG 判断已写明表达缺口、决定走“纯定制”或“配方 + 定制图解”之后读本文件。它不替代 Shotcraft 候选比较，也不是炫技素材库；目的是把“要做一个定制动画”变成一份可执行、可验收、可逐帧渲染的镜头需求（brief）。

灵感来源是 [mg-inspiration-index.json](mg-inspiration-index.json)：从公开合集 awesome-opus5-5-videos 的 282 条代码动画提示词中精选的 32 条，每条只有链接、中文摘要、可借鉴点与注意事项。

## 1. 使用顺序

1. **先有缺口**：directing.md 第 4 步写明现有配方为什么表达不了。没有缺口就不查索引。
2. **按用途筛选**：不要整份读取索引 JSON。运行本 Skill 的 `scripts/mg_inspiration.py`，用段落作用传 `--use`（可重复，`--list-uses` 查看标签），用制作定位的风格强度传 `--max-energy`，默认最多返回 4 条，例如 `python <本Skill>/scripts/mg_inspiration.py --use concept --use mechanism --max-energy 中等`。不按作者或热度挑。无匹配时如实记录，直接按第 3 节模板写。
3. **看样片**：打开 `preview_url` 正常速度观看，规则同 Shotcraft 样片检查。看不到就标“未验证动态参考”，不能只凭摘要说“参考了某效果”。
4. **需要细节再读原文**：`prompt_quality` 为“完整规格”或“结构模板”时，按 `raw_prompt_url` 读取原提示词，学习结构和约束写法。“一句话”类只借样片观感。
5. **写本镜 brief**：按第 3 节模板写到 `edit/shots/<shot_id>/brief.md`，用本片内容、品牌和口播重写，不整段粘贴原提示词。
6. **按第 6 节契约实现**，先静帧、后短测，再正式渲染。

记录要求：
- shot-selection 表中写入参考的 slug，并注明是否看过样片。
- assets.json 记“灵感来源：仅参考手法，重新实现”。
- visual-plan.json 的 `route` 仍记为 `mg`，不新增 route。

## 2. 口播适配：原提示词要翻译，不能照搬

合集里多数提示词为无旁白的炫技短片或音乐宣传片而写，放进口播片前必须逐条转换：

| 原提示词常见写法 | 口播片中改为 |
|---|---|
| 120 BPM，每拍一动；每个切点卡在鼓点 | 按旁白短语、停顿和重音写提示表（cue sheet），关键变化贴近语义词。只有音乐主导且已选曲的项目才保留节拍网格 |
| go all out / 作品集 / 越炫越好 | 按制作定位的风格强度降档。强度“强”的条目只用于定位允许的开场注意点或片尾落版 |
| 模型自写旁白、自配 TTS、自作配乐 | 旁白按 [inputs.md](inputs.md) 的输入模式；音乐与音效按本片意图和授权，不因原提示词而加 |
| 自由发挥文案、加口号 | `screen_text` 只从 `quote` 提炼，锁定逐字内容和顺序，不加未核实结论 |
| 英文字形变形、紧字距展示字体 | 换成已授权的中文字体，重新定行宽。变形后先确认中文仍可读 |
| 虚构 UI、演示数据 | 保留原提示词里“真实 UI、真实数据、不编数字”的条款，数据来源写进 assets.json |
| 全屏构图 | 竖屏人物口播时避开人物区和字幕区。安全区数值按当前平台官方规格核对 |

## 3. brief 模板

每个定制镜头一份，只写本镜需要的块，不留空占位：

```text
# <shot_id> 定制 MG brief
表达目标：一句话，让观众看懂什么（来自 directing.md 第 1 步）
MG 缺口：已比较的配方及其不足
灵感参考：<slug>（样片已看 / 未验证），借鉴点：……

锁定文案：屏幕上逐字出现的文字及顺序；禁止额外口号
对应口播：quote 原文 + 关键词时间（来自旁白转录，按帧）

视觉规范：色板（hex）、字体层级（展示 / 正文 / 标注）、质感词
形式概念：本镜唯一的形式规则（见第 4 节）

分镜（与 visual-plan.json 的帧窗口一致）：
  f0–f1  画面 / 主动作 / 落在哪个口播词
  f1–f2  ……
动作规则：缓动类型、过冲上限、入场次序、最短静止时间、运镜时长
禁用清单：本镜明确不用的效果

技术：Remotion 组件 / Canvas / SVG / Three.js；符合第 6 节确定性契约
自检：抽哪些帧、检查什么（见第 7 节）
```

合集中写得最好的提示词都有这些共同点，可作为写 brief 的标准：
- 文案锁定（techhalla-498547、gdgtify-929495）
- 色板与字体系统写死（techhalla-498547）
- 一条贯穿全镜的形式概念（gdgtify-929495、twoclipping-496100）
- 分镜写到 0.5 秒精度（howdevelop-733090）
- 缓动写成物理参数，例如“闭式弹簧、仅微小过冲”“临界阻尼落定”
- 列出具体禁用清单（twoclipping-000267）
- 全量渲染前先抽帧自检（verbove-268381、techhalla-498547）

## 4. 形式概念速查

一镜只选一个主形式，和 Shotcraft“每镜一个主动作”一致。

| 形式概念 | 适合的口播段落 | 参考 slug | 注意 |
|---|---|---|---|
| 词即结构：关键词变成画面结构件，逐句搭建 | 金句、观点落点、结论 | gdgtify-929495 | 先保证当句可读，再变成结构；需要真实字形路径 |
| 单一形状持续形变，内容随状态替换 | 产品功能串讲 | verbove-268381 | 容器先变形、内容后入场，避免文字重叠 |
| 下一场从上一场长出，一镜到底 | 章节内连续推进 | twoclipping-496100、jake11moran-414633 | 运镜宜慢，推拉约 1.5–3 秒；不适合跨章节跳题 |
| 容器逐步填满 / 从雏形到完成 | 步骤教程、建造过程、历史演进 | sarut0bisasuke-069973、retropunkai-277590 | 每步一个实体变化，配精确数字 |
| 穿过物体进入下一个世界 | 章节转场 | koldo2k-778767 | 先比较 Shotcraft transition 类卡片 |
| 真实模拟而非示意 | 科学、算法、概率类概念 | astrothewizard-618782、parkerrex-701462 | 模拟用固定种子；标出估算的不确定性 |
| 尺度跳跃：一点 → 界面 → 缩回一点 | 开场注意点 | dale-vaz-879074 | 界面须是真实截图 |
| 同一角色贯穿多个阶段 | 故事、情绪段 | loicrambo-980558、songkeys-384673 | 角色特征写成可检查清单（eric-khun-667455） |
| 物理隐喻 | 抽象算法 | anirockshady-032809 | 在 shot-selection 中记录隐喻映射，不当作事实 |
| 形式即内容：每层解释换一种风格 | 元话题开场 | emollick-019567 | 只用于短段，避免破坏全片统一 |
| 抹去即转场（沙画 / 白板） | 章节式长片 | michaelzsguo-782312、tak3sh8-441895 | 需要连续绘制状态，按帧重算 |

## 5. 风格词与实现约束

写风格词时，同时写出它在代码上的约束，避免只写形容词：

- **手绘白板 / 铅笔**：线条抖动按固定种子，每 2–3 帧换一次噪声；先查 Shotcraft `effects/line-boil`。可加轻微色差。
- **复古报纸拼贴**：半调网点、白纸边、柔和投影、胶片颗粒、暗角；颗粒按帧号取种子。
- **折纸 / 涂鸦**：少文字、暖色、圆角笔触，靠姿态讲故事。
- **沙画**：画面由上一状态“抹开”得到，不用交叉淡化。
- **高端极简**：一镜一想法、大量留白、单一强调色、一种干净无衬线体、遮罩出字；禁用粒子、光晕、抖动、弹跳缓动。
- **街头海报**：严格三色、三级字体、印刷错版只在冲击帧出现 2–4px。
- **像素风**：固定逻辑分辨率后整数倍放大、关闭平滑、固定调色板。

## 6. 确定性渲染契约（硬性）

所有定制 MG 必须能逐帧、可重复、可乱序渲染，否则不能与口播精确对齐，也无法稳定出片。这是 [production.md](production.md) 中“按帧驱动，随机固定种子”的具体化。

- **画面只由帧号决定**：Remotion 用 `useCurrentFrame()` 计算一切状态。独立 HTML 页必须暴露 `window.seek(t)`，并等待图片、字体、视频帧解码完成后才返回。
- **禁止**：
  - `requestAnimationFrame` 逐帧累加
  - `setTimeout` / `setInterval`
  - 自动播放的 CSS transition / animation
  - 跨帧保存的可变状态
  - `Date.now()` / `performance.now()`
  - 不带种子的 `Math.random()`
  - 按真实时间步进的物理积分
- **弹簧**：优先用 Remotion 的 `spring({frame, fps, config})`。自写时用闭式解，例如临界阻尼 `x(t)=1-(1+ωt)e^{-ωt}`。同一数值多次改变目标时，每次改变叠加一个从该时刻开始的弹簧，保持纯函数。
- **随机**：用带种子的伪随机数生成器，例如 mulberry32，种子取自元素序号或段落 id。
- **模拟与物理**：预先按固定步长算出轨迹数组，按帧索引读取；或每次从 0 按固定步长重算到当前帧。
- **循环片**：确保 `render(0)` 与 `render(T)` 一致。
- **HTML 路线出片**：用 Playwright 逐帧调用 `seek` 截图，再用 ffmpeg 合成。需要运动模糊时每帧渲染 3–6 个子帧取平均。不要录屏。
- **验证**：
  - 同一帧渲染两次，像素一致。
  - 按乱序（例如第 120、30、90 帧）渲染，结果与顺序渲染一致。
  - 有任一项不通过，不进入主片。

## 7. 自检

- 每段抽入场、峰值、落定、退出四帧，检查阅读顺序和可读性。文字在观众读完之前不能被变形破坏。
- 静音观看也能理解表达目标；有旁白时，关键变化与语义词的偏差在可感知范围内。
- 对照 brief 的禁用清单和色板、字体，逐项核对。
- 与前后镜头放在一起看一次，检查强度和风格是否连贯。

## 8. 边界

- 源合集没有附许可证，提示词和视频归原作者所有。只借鉴手法和写法，全部重新实现；不复制原片画面、文案、角色、品牌元素，也不以原作者名义发布。索引中涉及具体品牌或作品的条目（场馆、游戏、流媒体等）只借结构。
- 索引是 2026-09-28 的快照，不自动联网更新。用户要求时再从源仓库补充条目，并按相同字段写中文摘要。
- 条目提到的外部生成服务、TTS、音乐生成，都不代表本项目已获得相应权限或预算。
