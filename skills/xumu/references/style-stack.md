# 风格与技术栈：画面语言 → 绘制技术 → 渲染引擎

在第 3 步定好内容路线后使用：把定位里的风格落成全片主风格，再为每个动态段落选绘制技术与渲染引擎。手法与案例参考 xilo《零基础入门 Opus5.5 做视频》及其开源 Skill `xilo-opus-video`，按口播 B-roll 场景改写。

## 1. 三层分开决定

| 层 | 决定什么 | 记在哪 |
|---|---|---|
| 画面语言（style） | 观众看到的风格：干净界面、手绘、像素、胶片、3D…… | `project.md` 主风格；镜头 `style` |
| 绘制技术 | 用什么代码画出这种风格：SVG、Canvas、WebGL、Three.js、p5…… | `project.md` 或 shot-selection |
| 渲染引擎（engine） | 由谁逐帧输出视频：Remotion、HyperFrames、HTML 逐帧、Manim、FFmpeg | 镜头 `engine` |

选法：**先定画面语言，再选能做到它的最简单技术**。一种技术够用就只用一种；需要叠加时按"内容层 → 质感层 → 声音层"分层，每层能单独运行和检查。

## 2. 绘制技术

| 技术 | 擅长 | 口播 B-roll 常见用途 | 注意 |
|---|---|---|---|
| HTML / CSS / SVG | 界面、文字排版、图标描边、矢量图解 | 产品功能演示、流程图、金句大字、数据图表 | 成千上万的粒子交给 Canvas |
| Canvas 2D | 逐笔绘制的二维画面、粒子、像素 | 像素风、扁平插画、粒子汇聚、手绘线条 | 画布按设备像素比设尺寸，文字才清晰 |
| WebGL 着色器 | 逐像素计算的质感 | 老电视扫描线与弧面、胶片颗粒、网点、光晕、水面 | 作为质感层叠在 Canvas 内容上；渲染明显变慢（实测 3 秒片段从 7 秒变 48 秒） |
| Three.js | 3D 场景与真实镜头运动 | 产品转台、立体标题、点云、低多边形或体素场景 | 代码几何适合风格化；写实产品请用户提供模型文件 |
| p5.js + p5.brush | 真实笔刷方向、粗细与纸纹 | 彩铅、水彩、蜡笔、绘本式故事段 | 渲染慢，先测单帧耗时再定段落长度 |
| Manim | 公式与图形的精确变换 | 数学、物理、算法推导 | 画面偏素，色板和字体对齐主风格 |
| 人物抠像 + 代码场景 | 真人与代码画面结合 | 口播人物进入代码场景、分屏、环绕文字 | 见第 5 节 |

声音层：BGM 用授权音乐或用户提供的音乐；界面音效可用 numpy/scipy 合成，时间点直接取画面关键帧。旁白始终以锁定的母带为准。

## 3. 渲染引擎

| 引擎 | 实测状态 | 何时选 | 要点 |
|---|---|---|---|
| HyperFrames | **已在整片中验证**：7 分 41 秒教程片，白板一镜到底 + 真实录屏 + 圆形人像 + 视频卡片开场（HyperFrames 0.8.81；0.8.166 回归验证一致） | 白板/手绘世界镜头、大量视频层叠加、用 Python 生成 HTML 合成工程、GSAP 时间轴式动效 | HTML + GSAP 时间轴，按时间 seek 渲染；坑与工作流见 [制作路线与合成](production.md#hyperframes) |
| Remotion | 文档与插件就绪，尚未在序幕整片中验证 | 镜头以 Shotcraft 配方为主（其参考实现是 Remotion TSX）、React 组件化场景、需要 `@remotion/three` | 一切由 `useCurrentFrame()` 驱动；Canvas/WebGL 在组件内按帧重绘；首次用于整片时先做代表段试渲染 |
| HTML 逐帧 | 未在序幕中验证；mg-styles-15 的 15 支参考片用同一路线做成 | 单个独立动效段，或直接复用网页代码（含 `mg15:` 参考片源码） | 页面暴露 `window.seek(t)`（字体、图片、视频帧就绪后才返回），项目内 Playwright 脚本按帧截图，FFmpeg 编码；参考实现见第 10 节 |
| Manim | 未验证 | 数学推导段 | 用 Manim 命令出片，再进入合成 |
| FFmpeg | 已验证（剪辑、拼接、混音） | 抠像、叠加、拼接、混音 | 只做媒体处理，画面设计由上游决定 |

一部片只用一个主合成引擎；其他引擎渲染的段落作为视频素材放进主合成。选 Remotion 还是 HyperFrames 主要看镜头来源：以 Shotcraft 配方为主时选 Remotion，可直接复用其 TSX；以白板世界、自绘图解、大量录屏与人像叠加为主时选 HyperFrames。两者都可用时优先已验证的 HyperFrames。

**谁来决定**：技术与引擎属于实现细节，由总控按上表直接选定，在画面方案里用一句话说明理由（例如"白板一镜到底 + 多层录屏，用 HyperFrames"）。以下情况先问用户：用户已点名某个引擎；所选方案需要安装新的全局依赖；预计正式渲染超过约 30 分钟；需要付费服务。

所有引擎都采用**确定性渲染**：画面只由当前帧或时间决定，任一帧都能单独重渲，改一个镜头不影响其他镜头。完整规则（禁用项、弹簧与随机数写法、重复帧与乱序帧检查）见 [确定性渲染契约](mg-prompt-patterns.md#6-确定性渲染契约硬性)。

## 4. 风格目录

61 种画面风格按十类整理在 [风格目录](style-catalog.md)：教学解说、新闻纪实、界面产品、平面设计流派、插画手作、复古年代、科技氛围、东方传统、三维空间与组合方式。每种写明观感、标志动作、适合内容和现成实现。镜头的 `style` 字段取目录里的 key。

全片通常一个主风格，加至多一个辅助风格（例如 `clean-ui` 主体 + `kinetic-type` 章节标题）。段落之间换风格要有叙事理由，并保持色板、字体与动作强度连续。Shotcraft 配方适配时，皮肤（色板、字体、材质）统一到本片主风格。

## 5. 人物抠像进场景

口播人物或视频模型生成的人物交给抠像，其余画面由代码完成。

1. **素材**：绿幕拍摄最好；用视频模型生成时，要求纯绿背景、人物全身入镜。普通背景的口播素材需要人像分割工具，先确认本机可用并试一段。
2. **抠像**：`chromakey` + `despill`，颜色取抽帧中绿幕的实际值；先抠一帧给用户看边缘。
3. **场景层**：背景、大字、贴纸、分屏、环绕文字由所选引擎渲染。
4. **合成**：FFmpeg `overlay` 叠加；分屏可把同一段人物错开几帧叠多次。人物口型与旁白保持原有同步。
5. **节奏**：场景元素随旁白语义或音乐节拍变化，人物片段本身保持原样。
6. **作用范围**：同屏还有"原始"对比窗口时，抠像与换背景只作用于包装窗口（见 [制作路线与合成](production.md#共用规则)）。

## 6. 动作手感

- **缓动**：基础用 `smoothstep` 或 cubic in-out；匀速只给需要机械感的元素。
- **弹簧**：用闭式解，任一帧可单独计算。

  ```js
  function spring(x, w = 16, z = 0.72) {   // x = 距目标改变的秒数
    if (x <= 0) return 0;
    const wd = w * Math.sqrt(1 - z * z);
    return 1 - Math.exp(-z * w * x) * (Math.cos(wd * x) + (z * w / wd) * Math.sin(wd * x));
  }
  // 目标多次改变时叠加，保持动作连续：v(t) = v0 + Σ (v_i − v_{i−1}) · spring(t − t_i)
  ```

  同类元素全片用同一档：

  | 用途 | 手感 | w | z |
  |---|---|---|---|
  | 按钮、开关、指示条 | 快而利落 | 22–26 | 0.75–0.85 |
  | 卡片、容器、镜头 | 默认 | 14–16 | 0.70–0.75 |
  | 大字、3D 物体、Logo 定版 | 沉稳，几乎不回弹 | 9–11 | 0.85–1 |
  | 吉祥物、贴纸 | 活泼，明显回弹 | 16–20 | 0.40–0.50 |

- **镜头**：写明推、拉、跟随，主体至少占画面三分之一。
- **运动模糊**：快速运动多的段落每帧取 4 个子帧叠加，渲染时间约变 4 倍，先告知用户。
- **节拍**：有音乐主导时，状态变化落在拍点，最大的变化落在重拍；口播主导的片子以语义词为准。

## 7. 本片避开清单

没有约束时，AI 动画会回到同一种默认样子：深色背景、居中大字、全部淡入淡出，以及无理由的发光、粒子爆炸、渐变和角落里多余的标签与边框。确认风格时，在 project.md 写下本片的避开清单（3–6 条，具体到可检查），制作和验收都对照它。风格本身需要深色时（CRT、夜景、霓虹）照常使用，排版与运动另行设计。

## 8. 成本与预览

- 代表帧确认画面语言；2–4 秒短测确认以动作为卖点的段落（界面变形、节拍卡点、转场）。
- 用短测的单帧耗时估算正式渲染：单帧耗时 × 总帧数 × 子帧数 × 1.3。着色器、p5 笔刷、运动模糊是三大耗时项，长片先出低清版确认节奏，再精修。
- WebGL 先渲一帧确认着色器生效：`getContext('webgl2', { preserveDrawingBuffer: true })`，每帧画完调用 `gl.finish()`。
- 被缩放或含文字的元素去掉 `will-change`，保持文字清晰。
- 字体文件放进项目目录，用 `@font-face` 本地加载，等 `document.fonts.ready` 后再开始渲染。像素风中文在逻辑画布上至少 18px。
- 多画幅时用版式函数布局，每个画幅单独调整文字与界面位置，从同一时间轴分别渲染。

## 9. 风格模板的沉淀

风格目录里的条目分三级：

| 级别 | 有什么 | 现状 |
|---|---|---|
| 有模板 | `assets/templates/<style>/`：可运行的构建库 + 页面骨架 + 演示脚本，配一份做法文档 | `whiteboard-world` |
| 有参考片 | 外部参考库里一支完整的 10 秒参考成片：提示词、确定性源码、可检验的标志特征 | 15 种，见第 10 节 |
| 有起始稿 | 外部参考库里现成的起始页面，可改造成模板 | bang-motion 的 6 种解说风格（`cartoon-collage`、`visual-journalism`、`white-catalog`、`vintage-engraving`、一镜到底连续动作、`cartoon-stage`），位于 `refs.bang_motion/assets/` |
| 只有条目 | 观感、标志动作、适合内容、`gn:`/`hf:` 组件指引 | 其余风格 |

某个风格第一次在实际项目中用到并通过验收后（有参考片的风格从参考片源码起步更快），把这次的设计规范（色板、字体、动作档位、避开清单）、可复用的构建代码和一段演示整理进 `assets/templates/<style>/`，写一份做法文档，把目录条目标成"有模板"。模板来自通过验收的成片，不预先凭空编写。

## 10. 风格参考片（mg15）

[mg-styles-15](https://github.com/Vincentwei1021/mg-styles-15)（MIT）为 15 种动态设计风格各做了一支 10 秒成片，附完整提示词与全部源码，画面与配乐都由代码生成。目录里标"有参考片"的 15 个条目各对应其中一支；`crt-film` 的 VHS 做旧也可参考 `mg15:10-synthwave`。`motion_index.py fetch` 只取提示词与源码，不下载成片视频；成片在线观看（`show` 输出的 `preview_url`）。

- **选风格**：给用户的 2–3 个方向里有参考片时，附上在线成片链接，比一张代表帧更能说明动态。代表帧仍按本片内容和画幅出。
- **标志特征当验收清单**：`motion_index.py show mg15:<id>` 列出这种风格的视觉特征和关键技法（带具体参数，如"白描边 8–12px""入场 0→1.15→1.0 约 8 帧"）。选定后写进镜头 brief 的风格规范，整片自检的"风格一致"按它逐条核对。
- **翻译成口播节奏**：参考片是无旁白、音乐驱动、十秒内全力展示的作品，按 [口播适配](mg-prompt-patterns.md#2-口播适配原提示词要翻译不能照搬) 转换：节拍网格改为旁白提示表，能量按定位降档，文案只从原话提炼，画幅按本片（参考片多为 16:9，综艺花字为 9:16）。保留的是标志特征，不是原片的故事、品牌名与配色。
- **复用源码**：参考片页面暴露 `window.renderAt(t)`，与本 Skill 的 `window.seek(t)` 契约同义，截图脚本调用其一即可；仓库的 `harness/render.mjs` 是一份可参考的逐帧截图实现。复制进镜头目录的代码记入 assets.json（来源与 MIT 许可），按 [确定性渲染契约](mg-prompt-patterns.md#6-确定性渲染契约硬性) 做重复帧与乱序帧检查后再进主片。
- **素材与依赖**：仓库不含字体文件，按其字体清单或本片已授权字体替换；照片与纹理为 CC0 或公有领域，仍逐项记录。`soft-3d` 需 Blender，属于新依赖，先取得同意。仓库的 `lib/audio` 可代码合成配乐，乐器采样需另取，用作本片 BGM 前按声音策略确认。
- **评审**：仓库的 `rubric.md` 是一份严格的独立评审提示词（风格还原、概念、动作、排版、质感、声音、技术七项），可在 [独立终检](qa.md#独立审查) 时参考它的维度与"附时间码和具体改法"的要求。
