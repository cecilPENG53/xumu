# 制作路线与合成

## 所有路线共用

只实现已确认或明确授权自主决定的镜头。每个任务给出唯一 ID、局部帧起点 0、全片起点、时长、画幅、fps、风格、素材、字幕安全区、声音政策和验收帧。以整数帧为主，不在多个工具里各写一份秒数。

项目输出放 `edit/animations/<shot-id>/` 或 `edit/assets/`。依赖优先项目内安装；不更新原 Video Use 或已安装的 Shotcraft。外部组件/素材记录来源和许可要求，商业使用按具体资产许可处理，不能把仓库说明扩张为所有依赖免费。

## A. 原片与 B-roll

原片在 Video Use 中完成主剪辑。B-roll 指补充画面而非特定引擎：现有录屏可直接插入，不必绕 Remotion。检查起止、原始声轨、构图、授权和保密信息。主旁白继续播放，B-roll 自带声音默认静音；需要保留的拟音另作明确音轨。

## B. Shotcraft + Remotion

先完成 [Shotcraft 导演接入](shotcraft-direction.md) 的候选比较、样片检查与全片分镜，再复制所选准确源码/公共组件到镜头项目，修正导入、素材路径和依赖版本。保留命门参数，参数化文案、颜色、目标值、尺寸和布局。最终同片字号/色板不应由每个 demo 自行决定。

这是整片导演之后的逐镜头实施路径，不是把 Shotcraft 限定成偶尔调用的小装饰。沿总控已定的镜头组织制作，不启动竞争的产品宣传片时间线，不强制重选模板/音乐。配方时值与主片不相容时回到选择记录换卡或修订方案；用户指定动作需说明差距，不能硬压缩或偷偷换成普通淡入。

用可用 Remotion Skill 的创建、markup 和 render 参考；按帧驱动，随机固定种子，字体和素材在渲染前可用。多镜头并行只共享只读设计规范，输出独立文件。先静帧再短测，再正式渲染。

## C. 定制 MG

先按 directing.md 的 MG 判断记录现有配方不能表达的真实关系、计算逻辑或专属图解，以及为什么静态呈现不够，再用 React/SVG/Canvas 等实现。不要仅因内容是中文、流程或图表就默认纯定制。Remotion 不负责自动理解文案；总控和制作 Agent 负责设计。

无适合卡片时可以定制，不凭空要求图像或视频模型；也可用定制图解承载内容、Shotcraft 运镜引导注意，标明两者边界并分配主次。数字和文字应可精确控制、可修改；不能把动效美观当成数据正确。复杂数学或正式推导可按需求选可用 Manim，不为工具齐全而引入。

动手前按 [mg-prompt-patterns.md](mg-prompt-patterns.md) 写 `shots/<shot_id>/brief.md`，并遵守其第 6 节确定性渲染契约：Remotion 用帧号计算一切状态，独立 HTML/Canvas/Three.js 页面暴露 `window.seek(t)` 并用 Playwright 逐帧截图出片，不录屏。重复帧像素一致、乱序帧与顺序帧一致两项检查不通过的镜头不进主片。HyperFrames 效果库条目本身是可逐帧定位的 HTML 合成，用 `hyperframes render` 单独出片（叠加层用 `--format webm` 或 `mov`），同样抽帧验证后再交回主时间线。

## D. 插画 + 有限动作 2D

区分静态完整插画与可动资产。独立移动的手臂/头部/道具需分层或不同姿态；镜头推近只需要完整图，但不能宣称人物已具备任意动作。

制定角色外观、场景与道具一致性约束 → 生成或复用图像 → 审核 → 分层/姿态准备 → Remotion 编排运动。可以完全不经过视频模型。图像生成使用当前可用的图像 Skill，先读其规则；不借 Shell 绕过其编辑/调用要求。

没有图片且不使用付费模型时，可用原创 SVG/Canvas 矢量绘制或已有授权的分层资产制作简化插画角色、场景与道具，不必等待图像生成接口。先用代表性构图确认画风与动作能力；用户要求复杂精细画风时，不擅自降为几何小人。已有栅格图的生成/编辑仍遵守对应图像工具规则，不能把“矢量绘制”当绕过编辑要求的理由。

## E. 外部视频与 3D

先明确需要复杂动作还是可编辑模型。复杂视频表演可评估图生视频；可编辑 3D 需实际几何/模型/材质/动作，不把 MP4 当模型。不能按用户含糊语音识别的名称猜测模型版本。

生成任务包至少含：shot_id、时间线 revision、目标时长/画幅、主动作、连续性约束、参考文件、正向提示词、必要的避免事项、是否需要声音、输出文件约定、验收标准。原文、内部数据和凭据不无差别上传。

状态：planned → awaiting_approval / waiting_external → rendered → verified。只有接口可调用、账户可用、上传和费用范围已获授权才提交。保留真实 job ID 和费用/次数记录；不编造进度。异步任务有正式轮询或等待机制才使用，跨回合不声称后台继续工作。

未接通时交付上述任务包，由用户生成后回收文件并探测，不因缺接口而重新询问已明确的创意。重试至多 2 次且受剩余预算约束；达到上限、持续失败或必须换平台时停止该镜头，提出换路线或等待的选择，不悄悄改用户指定效果。

## 合成实施边界

### Video Use 底片路线

先完成主剪辑和调色的底片；逐片段提取后无损拼接，片段边界短淡入淡出。最终覆盖层时移后叠加，字幕最后。当前本机 `helpers/render.py` 只消费 `file/start_in_output/duration`，不读取 x/y 等自定义字段；只映射底片音频，覆盖素材音效不会自动混入。

简单同画布、不透明、无自带声音的全屏插入可以沿该接口。涉及 Alpha、SFX、画布变换时，在项目内生成单独合成脚本或受控适配副本；不要声称原 helper 已支持这些能力。不把新协议直接传给原 helper。

### 无视频底片路线

音频/文案模式在 Remotion 主 Composition 中按计划组装连续背景镜头，或逐镜头渲染后用 FFmpeg 组装完整画面，再加入锁定的旁白。背景可为实际片段、插画、图解或有意设计的色场；都必须显式覆盖全片。不得把音频路径传给要求视频流的提取器。

初版优先硬切与片内入退场。交叉转场若使镜头重叠，要由专门的时间线扩展处理，不绕过当前校验器并把重叠当已支持。

### 透明与声音

- 人物覆盖层须移除 demo 的背景，输出全画布 Alpha 素材，元素位置由画布内部控制。普通 H.264 MP4 没有可用的透明覆盖通道。
- Remotion 透明导出遵循当前官方 render 参考（例如 VP9 WebM + PNG 帧 + yuva420p）。本机 FFmpeg 曾需在该输入前指定 `-c:v libvpx-vp9` 才保留 Alpha；正式执行先做实际小样。ProRes 4444 可作另一条验证路线。
- 素材实际 dimensions/fps/duration 必须与计划对齐。小样检查半透明边缘、开始和结束帧；`setpts=PTS-STARTPTS+T/TB` 保证局部第 0 帧落在指定起点；窗口应按半开区间处理，避免结束多出一帧。
- 主旁白只混一次。动画 SFX 单独轨道按局部帧偏移加入，BGM 单独控制，生成镜头自带人声默认静音。
- 字幕在所有覆盖画面后烧录（例外：使用 HyperFrames 背后字幕的人物段已自带字幕，按 [backends.md](backends.md) 的衔接规则处理）；混完声音后对最终音轨做响度测量和必要的两遍归一化，检查峰值/削波。不要在每层分别归一化后就认为最终混音安全。
- Windows 路径含空格、中文、盘符时按实际库的转义规则处理；优先参数数组与 JSON 文件，不拼接含外部文本的 Shell 命令。SRT/libass 与 concat 路径需做实渲验证。

## Workbench

仅用户需要完整可视化编辑时读 Shotcraft 的 workbench 参考，并实现 `WORKBENCH` 清单、组件 props/schema 和帧级一致性检查。一个渲染后的 MP4 不会自动恢复为原始可编辑组件。未经导入/渲染测试不宣称工作台就绪；普通成片任务不必为此迁移全片时间线。
