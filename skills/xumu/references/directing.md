# 内容到画面：先判断表达，再选镜头与 MG

## 先做叙事判断

先承接 project.md 中的 [制作定位](production-profile.md)，将受众、内容目的、表达风格和时长转成段落目标；章节长片先组织论述与章节，再选择局部镜头。模糊的平台风格名不能替代这些判断。

用原文和必要的素材检查判断这个段落需要观众理解的对象、关系或情绪；不使用固定打分公式或每 N 秒插一次动画的配额。把主要信息、例子、证据、情绪和过渡分开。镜头提供理解价值，而不是重新把整句字幕动画化。

优先保留：可信的人物表达、具体成果、真实操作、已有高质量素材。动作和剪接不能制造原文没有的因果关系。抽象故事用视觉隐喻时记录映射；不能把隐喻或再现当事实证据。

## 路由

| 内容需要 | 推荐起点 | 不应机械套用 |
|---|---|---|
| 观点、情绪、承诺 | 原人物镜头或克制背景 | 每次出现关键词都加特效 |
| 真实操作、真实成果 | 先确定真实素材，再比较直接展示与 Shotcraft 推近、聚焦、陈列等方式 | 以“真实 B-roll”为由跳过镜头设计；合成假 UI |
| 顺序、循环、汇聚、分支、对比 | 先判断静态图/原片能否讲清；需要动态时比较机制配方，再决定适配或定制 MG | 把不同机制都画成三节点循环；先写 MG 再找理由 |
| 指标变化 | 有来源的数据；比较库中数据镜头与专属图解所需逻辑 | 编百分比；把装饰数字当数据可视化 |
| 人物故事、空间情境 | 插画分层与姿态；必要时外部视频 | 以卡片移动替代所有角色表演 |
| 可编辑三维结构与动作 | 代码几何或专业三维资产 | 把生成视频宣称为可编辑模型 |

可混用但保持字体、色板、图形语言和叙事空间连续。不要强制继承 Ink Press 风格；口播 IP 以用户品牌为主，展示真实产品时保留其识别特征。中文行宽、字体文件、竖屏人物区域与字幕区都在风格检查中确认。

## 内容可视化设计步骤

1. 用一句话写解释目标，例如“让观众看懂三条输入如何经过分类分发”，而非“做高级科技动画”。
2. 建立实体与关系：什么是来源、规则、结果？哪些东西保持身份？哪些是真实数据？
3. 安排阅读顺序：先对象，再变化，再结果；关键落点跟随语义词，不默认所有元素一起出现。
4. 指定素材要求：真实截图、SVG、分层角色、姿态、背景、视频片段或三维模型。不存在的资产标记待制作，不能写成已完成。
5. 按 [Shotcraft 导演接入](shotcraft-direction.md) 比较动态段落的首选/备选镜头，并完成下方 MG 判断。查摘要覆盖镜头库，入围才读全文和 demo；不要求把整个库渲染一次。
6. 先完成内容到镜头映射，再组织整片节奏和完整分镜。按旁白长度、信息量和动作可读性安排停留；长图解不能硬压进极短窗口。必要时换镜头或减少一镜的信息量，不擅自拉长或重配原声。

## 是否需要定制 MG：每个动态段落先回答

1. **不动是否更清楚？** 人物情绪、可信表达、短结论或细密证据适合直接保留/静止阅读时，选择不加动画，不设置特效配额。
2. **要引导视线，还是解释机制？** 展示作品、从全貌到细节、切换章节、引出重点，先比较 Shotcraft 的运动/揭示/转场，这些通常不需要重造图解。
3. **配方能否准确表达实体关系？** 只需换素材、中文、色板、布局、实体数量，且不破坏动作语法时，是配方适配。非英文内容或真实图片不是“只能定制”的理由。
4. **缺口究竟是什么？** 独有因果链、随真实数据变化的图表、算法/流程规则、空间结构或行业专属示意，现有配方无法忠实表达时选定制 MG；写明关系与所比较配方的不足，不只写“更高级/更灵活”。
5. **能否混合？** 例如自绘流程节点解释业务机制，外层用配方运镜聚焦；区分借用的运动与原创的图解，不在同一瞬间叠加多个主动作。
6. **定制怎么写？** 查找顺序固定：Shotcraft 镜头卡 → （仅当用户点名的效果在 Shotcraft 中没有时）HyperFrames 效果库搜一次，见 [backends.md](backends.md) → 灵感索引与从零定制。不对每个段落都走一遍三个来源。第 4 步缺口成立后，读 [mg-prompt-patterns.md](mg-prompt-patterns.md)：按段落用途从 mg-inspiration-index.json 入围 2–4 条并看样片，选一个形式概念，写本镜 brief（锁定文案、视觉规范、分镜、动作规则、禁用清单、自检）。灵感条目多为无旁白炫技片，按该文件第 2 节翻译成口播节奏和本片风格强度，不照搬。

`Shotcraft / 定制 MG` 是设计与实现来源，`Remotion` 是引擎，不是三个互斥工具。素材类型也不决定 route：用真实海报适配 Shotcraft 仍可记为 shotcraft；真实属性留在 assets.json。混合镜头标清两部分，主计划按主要实现 route 记账，必要时拆为有意义的 shot_id，不发明校验器不认识的新 route。

## 交给用户确认的画面安排

先给选择表：内容摘句｜表达目的｜首选镜头与动作｜备选/不动｜是否定制 MG 与理由。用中文解释效果，卡名可附后；没有合适备选时说明原因，不硬凑数量。

再给完整分镜：剪后时间段/shot_id｜实际画面与主动作｜素材来源｜入场→落点→停留→退出｜字幕/转场/声音。说明开场注意点、信息展开、重点镜头和收尾如何衔接。总代价或新增外部生成单独说明；内部精确帧数以 visual-plan.json 为唯一事实源。

先选代表性关键帧验证品牌、中文排版和构图，运动手法用短测验证。不把所有成片都先渲完才问喜不喜欢。用户点名风格或镜头即为约束；没有点名时给出推荐理由，不要求用户懂卡片名称。

## Shotcraft 的定位

它是动态段落的选镜头与动作来源，不是末尾装饰库，也不替代内容判断。精确解析、样片回收、动作继承、节奏编排与记录要求集中在 [shotcraft-direction.md](shotcraft-direction.md)。库里的背景、占位 UI、英文和固定坐标需适配，不能把演示数据当作本片证据。

## 原声与文字分工

- `quote`：用于追溯的实际口播原文，不是新配音稿。
- `screen_text`：允许在不改变意思的前提下提炼，不能增加未核实结论。
- subtitles：准确对应实际声轨，不能把提炼后的标题当逐字字幕。
- 需要改变旁白才能成立的画面，先回到脚本/剪辑策略，不能以动画需求为由偷偷改原声。
