# Video Shotcraft：内容选镜头与整片节奏

有动态呈现、运镜或镜头包装需求时，在写 Remotion 前读本文件。只剪口播、只加字幕或明确不加动画时不强行选卡。用户要 Gallery 效果时，将动作还原与镜头表现列为交付目标，不能靠一个小划线代表完成整套需求。

## 1. 正式接入，保持一个总控

从当前可用的同名 Skill 或相邻 `video-shotcraft/` 目录解析 Shotcraft 根目录，完整读取其 SKILL.md。依据现有协作方式读取原版 `references/pipeline.md`（自主）或 `references/guided-free-creation.md`（共同创作；制作时再读 pipeline）。将其“产品功能”映射为本片的内容段落、证据、演示对象或叙事转折，采用内容选镜头、分镜组织和实现规则。

这是 VV 主导的组合工作流：已确认的输入、旁白、风格和自主/共同协作方式继续有效，不重复询问三种宣传片模式，也不强制转成 Ink Press。用户明确要整套模板或独立产品宣传片时才进入对应完整路线。画幅、原声与真实性约束由总控维护；不把产品宣传片默认的强鼓点、三维运镜或高能收尾变成所有口播的规定。

## 2. 内容到镜头候选

1. 按语义段列原文、表达目标、适合保留人物/证据还是动态呈现、可用素材、主计划 shot_id 与时间预算。先做内容判断，不以镜头名倒推文案。
2. 对需要动态的部分，扫描 `references/shots/` 全部卡片 frontmatter 的用途、能量、建议时长、限制；可用 `gallery/api/library.json` 完整摘要初筛，再回卡片补齐缺失约束。记录索引版本/哈希和扫描范围，别把记忆中的两张卡当成全库检索。
3. 每段比较首选与可行备选：素材是否满足条件、动作是否表达内容、入场和阅读停留是否放得下、是否与前后镜头重复，以及是否符合制作定位的构图、风格强度、观看尺寸与章节作用。原片/静态展示可作备选；无合适候选时如实记录，不捏造名称。不按平台名固定分配卡片。
4. 阅读入围卡和准确 demo、查看动态样片；按 directing.md 的 MG 判断选择配方适配、配方与定制图解结合、纯定制，或取消无用动画。不能只以“定制更方便”为由跳过比较。
5. 用户点名卡/变体或具体动作时，将其视为约束；名称不明确先按目录核对并用中文解释。材料不满足或时长不足时说明取舍，不悄悄换成淡入。已授权自主判断则记录定案，否则随画面方案一并确认，不逐卡机械提问。

没有“每 3 秒换镜头”“至少用 5 张卡”或 Shotcraft 占比指标；要求的是相关内容经过合理选择，而非凑数量。

## 3. 精确解析与样片检查

- 核对索引 `cards[].name`、`styles[].key`、`source`、`styles[].media.url`。索引与配方冲突时记录并核对，不凭相似名称猜实现。
- 按卡片“参考实现”定位 TSX，完整读取选中代码和必要组件；保留关键时值比例、缓动、遮罩时机、路径与已知坑。适配素材、中文、品牌、坐标和必要构图，不用近似动画替代已调配方。
- 动态 MP4 不一定随 Git 下载。缺本地文件时先检查所选样式的在线 Gallery/媒体地址；需本地参考时先检查 `gallery/fetch-media.sh` 的行为，再选合适的回收方式。只取本次入围公开样片，不默认下载整个媒体库，不执行未经检查的脚本，不上传用户素材来换参考。
- 对入围动作正常速度观看，必要时抽入场/峰值/落定/退出帧，记录动作拆解。网页摘要、源码和单张截图均不等于看过动态效果。
- 样片确实不可访问时标“未验证动态参考”，可用准确 demo 做本地短测验证自身实现，但不能宣称已对照原样片；用户要求忠实复现时明确差距，不偷偷降级。
- “仅供参考、需自定义实现”的变体不默认当成熟模板推荐；用户点名后解释风险。只复制项目用到的实现，不修改上游 Skill。

## 4. 组织整片，不逐段贴卡

按叙事作用排动作强弱：建立关注对象 → 展示/解释 → 重点落点 → 留白或回到人物 → 收束。可按故事、教程、案例、方案调整，不是每片必须五段或高能收尾。

- **每镜一个主动作**：推近、海报翻滚、文字揭示不在同帧抢焦点。多对象有阅读次序，落定后再交给下一个焦点。
- **镜头对比**：全貌与细节、静与动、人物与证据、解释与结果交替。不整片重复“白底 + 两张卡滑入”，也不连续堆翻滚、闪白和急推。重复手法只在明确的系列比较/节奏结构中使用并说明目的。
- **动作弧完整**：为准备/入场、变化、语义落点、阅读停留、退场分别留时间。沿用配方已调时值；文字/品牌落定通常至少约 1 秒、批量动作后约 0.5 秒是检查起点，按内容和配方调整。阅读停留指焦点可读，不要求所有运动冻结；配方明确要求连续运动时保留该动作，可在后续稳定展示镜头补足阅读时间。窗口不够则换卡、减少同镜信息或回头讨论时长，不把动作一律加速。
- **口播先行**：关键变化靠近语义词，停留覆盖读图过程。原声模式不为音乐切词/变速；音乐主导且用户已选曲时才加载节拍规则。拟音和 BGM 由本片意图决定，不因库里有音效就使用。
- **转场有依据**：章节可较强，同一证据细节推进宜保持空间连续。字体、配色、材质和动作强度协调，不能直接拼各 demo 原皮肤。
- **人物回归**：承诺、情绪、解释收束适合回到人物；音频/文案模式以证据或设计的稳定画面承担停留，持续覆盖全片。
- **对比真实性**：擦除适合有可解释对应关系的状态；构图不同可分屏/翻面对照，不暗示像素级连续变换。没真实网页时可让海报/图像充当主角，不伪造产品操作。

完整分镜须看得出每镜“为什么在这里”，不只列卡名。静态风格通过后仍需验证关键动作短测，再制作全片。

## 5. 最小决策记录与验收交接

在 project.md 或 shot-selection.md 按实际段落填写，不保留占位行：

| shot_id / 内容 | 表达目标与素材 | 首选卡·变体 / 主动作 | 备选与取舍 | MG 是否需要及具体缺口 | 定制灵感 slug（样片已看/未验证） | 样片/代码证据与确认状态 |
|---|---|---|---|---|---|---|

“定制灵感”列仅在该镜走定制 MG 时填写，来源为 [mg-inspiration-index.json](mg-inspiration-index.json)；不需要定制则留空，不为填满而硬找参考。

补一段全片节奏说明：注意点、信息展开、重点与呼吸位、人物/证据切换、转场依据、声音安排。精确帧数由 visual-plan.json 派生，不维护另一份独立时序。

核心运动来自配方则记 `route=shotcraft`，填写真实 `card/style_key`；真实素材另记 assets.json。混合镜头说明原创部分，不称全部来自 Shotcraft。plan_tools 仅验证结构/时间/文件，不自动验证候选选择、名称真实性、动作还原或节奏；这些由导演自检和独立审查核对。

交付简述实际配方、定制 MG，以及未采用的用户指定动作和原因。源码能编译或成片能播放，不代表完成了 Gallery 镜头效果要求。
