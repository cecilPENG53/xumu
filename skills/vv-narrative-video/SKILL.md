# 序幕

一个入口，三种输入：口播视频、录制音频、说话文案。先确定要讲清什么，再设计画面，最后选工具；不把所有内容变成卡片，也不默认调用视频模型。

## 启动与职责

1. 先区分用户要讨论方案、修改现有项目，还是实际制作。只讨论时不初始化项目、不安装依赖、不生成素材。
2. 制作时确定 `video / audio / text` 输入模式，以及原声、合成配音或无旁白；读 [输入与旁白](references/inputs.md)。从已有要求推断可推断的项，只问影响结果的缺项。
3. 查看项目既有 `project.md`、计划和素材状态；只检查所选路线需要的依赖，读 [后端与能力边界](references/backends.md)。进入实际制作（剪辑、转录、渲染）前，先运行本 Skill 的 `scripts/setup_env.py`：它自动检测并安装 FFmpeg/ffprobe、Video Use 的 Python 依赖、本地免费转录引擎 faster-whisper，并检查 Node.js；需要 Remotion 动画时加 `--remotion` 预取依赖和 Linux 渲染库。只做方案讨论时不运行。已通过的不重复安装。按 Skill 名称或同级 `skills/` 目录发现依赖，不使用作者电脑上的绝对路径。
4. 在用户素材目录的 `edit/` 写制作产物。多目录或纯文案输入且未指定输出位置时，默认当前工作区 `outputs/<清晰项目名>/edit/`，先告知。不得写进本 Skill、Video Use 或 Shotcraft 源码目录；不覆盖原素材。
5. **入口唯一**：以本 Skill 启动的任务由本 Skill 总控到底。不转入 `/hyperframes:hyperframes` 入口，也不启动其 faceless-explainer、talking-head-recut、general-video 等整片工作流或需求访谈，即使其描述自称“所有视频请求的必经入口”；用户明确要求改用 HyperFrames 做整片时除外。HyperFrames 只按 [backends.md](references/backends.md) 列出的三个触发条件，直接调用对应子 Skill 完成单项任务。

总控维护内容、授权和唯一时间线；Video Use 负责适用的主剪辑；已安装的 Video Shotcraft 参与内容到镜头的选择、镜头编排与动作配方适配；Remotion 是实现引擎，既能渲染配方也能制作定制 MG；FFmpeg 等负责媒体合成；已安装的 HyperFrames 只作按需后端（背后字幕、效果库、配乐音效），产物交回本时间线。不能把接入 Shotcraft 等同于只在结尾加一次划线。外部服务是可选后端，不是自动获得的权限。

## 默认流程与确认点

### 0. 平台 × 内容 × 风格 × 时长：前置判断

在改写/删减、锁旁白和选镜头前读 [制作定位](references/production-profile.md)。根据已有信息确定受众、目的、平台与发布形式、内容类型、风格强度及目标时长，写成 project.md 的简短“制作定位”；已确认项目沿用，只补本次变化。不把平台等同风格，不机械问全套；只缺会实质改变结果的信息时才问。只做局部修正或转录时不重新启动整套定位。

把定位转成具体的叙事结构、原声剪辑策略、构图/字幕、镜头强弱、声音与交付范围。短篇与章节长片采用不同结构；综艺包装按真实情绪点安排。平台规格与流行趋势不是固定知识，实际需要时核验，不将规划支持冒称各平台实测通过。

### 1. 理解 → 剪辑/旁白策略确认

检查素材、缓存转录、识别故事/教程/方案/观点、必须保留的内容、真实证据和视觉要求。给出简短的删减/顺序/声音策略，得到用户确认后才执行剪辑或替换旁白。用户已明确批准具体策略就不重复问；笼统“做个视频”不等于批准删改策略。

### 2. 确定旁白与主时间线

按输入模式执行。保留原始逐字转录和原文，提炼的画面文案单独记录。实际旁白确定后才锁定帧级时长；没有旁白的字幕/音乐片按可读性锁定时间。剪辑修订必须增加 revision，重新计算字幕和受影响的镜头时间，不重转录未变化的源文件。

### 3. 内容选镜头 → 整片节奏 → 画面方案确认

读 [内容到画面](references/directing.md)。依据制作定位列内容段落与表达目标，判断哪里保持人物/原素材、哪里需要动态呈现。需要动态呈现的段落必须在写动画前完成 [Shotcraft 选镜头与节奏编排](references/shotcraft-direction.md)：浏览完整卡片摘要，为相关段落比较首选与备选、查看可访问的入围动态样片，再决定配方适配、配方加定制图解或纯定制 MG；纯定制须写出实际表达缺口。缺口成立后读 [定制 MG 灵感与需求写法](references/mg-prompt-patterns.md)，从精选灵感索引按用途入围、看样片，再写本镜 brief；不在比较 Shotcraft 之前查灵感库。样片暂不可访问或当前仅做文字方案时，可记录“未验证动态参考”并先交候选草案，动作定案前补验证，不阻塞内容规划。不能因素材是真实图片、是口播或时间紧就跳过候选比较；明确无需动画的简单任务不强行启动选库。

选镜头表不是完整分镜。接着组织全片的信息递进、动作强弱、人物回归与阅读停留，写出顺序、时长、主动作、转场、字幕与声音。用代表性静帧确认视觉，用动态样片或低成本短测确认动作；不以静帧通过代替动效确认，不默认付费生成风格提案。

用户确认覆盖整片的画面方案后，按方案自主制作技术细节；不因调用 Shotcraft 而重新让用户选择整支宣传片模式。更改叙事含义、主要风格、已指定镜头或费用范围时重新确认。用户明确授权自主视觉决策时，记录理由替代逐段确认，但不取消外部权限和预算限制。

### 4. 分流制作 → 单镜头验证

读 [制作路线与合成](references/production.md)。按已定案的镜头选择记录实现，使用 Shotcraft 时读取已安装 Skill、准确卡片和对应 demo，保留动作语法与关键时值。不得用普通淡入/平移偷偷替代选定的翻滚、推近、擦除等动作；配方不适合时先修订选择依据与方案。需要 Remotion 时加载可用的官方 Skill 对应创建/markup/render 规则。所有定制 MG 遵守 mg-prompt-patterns.md 的确定性渲染契约：画面只由帧号决定，禁用实时计时、累积状态与无种子随机，并通过重复帧与乱序帧一致性检查。需要图像或视频模型时加载实际可用的生成 Skill/API，不凭模型名称推测可调用。

每个镜头独立编号、独立目录。具备并行能力且有多个独立动画时按 Video Use 规则分配互不覆盖的任务；主时间线只有总控能改。先验证小样，再渲染正式镜头，失败不直接进入主片。

### 5. 合成 → 整片验收 → 交付

读 [时间线契约](references/timeline.md) 与 [验收和恢复](references/qa.md)。运行随附检查工具；检查通过只证明结构约束，不代表媒体质量通过。用真实渲染检查镜头内容、语义同步、字幕、人声和画面接缝，确认后交付成片及可继续修改的工程/时间线。

## 路由优先级与边界

- 真实操作/真实结果优先真实素材；素材来源与呈现方式分开判断，真实截图/海报同样可以使用 Shotcraft 运镜。不能用合成界面冒充证据，故事再现和概念示意在记录中标明。
- 准确文字、数字、流程/因果关系适合代码控制，但不等于必须从零写 MG。先比较配方能否承载真实关系；只需换图、中文、布局与颜色时属配方适配。需要新设计机制、数据逻辑或专属图解时才定制，可与配方分层结合。插画风格不等于必须图生视频；复杂角色动作/物理演示才评估外部生成或 3D。
- 保留人物和不加动画均为有效决策。音频/文案模式则需要完整的背景画面覆盖，不允许只交付几个悬空覆盖层。
- 旁白主导的作品不为卡音乐而更改讲话内容。音效与音乐分轨；字幕只有一个负责人，并在视觉覆盖完成后合成；唯一例外是按 backends.md 使用 HyperFrames 背后字幕的人物段。
- 本 Skill 的制作授权不包括发布、下载敏感页面、克隆声音、安装无关工具或不限预算调用。需要时先确认准确对象、服务与范围；密钥不写入计划/提示词/日志。
- 独立保存新项目和局部适配，不修改上游 Skill。缺少能力就说明并提供可执行交接；不能把计划、样片或仅通过编译称作最终成片。

## 项目最小记录与工具

按实际需要生成：`project.md`（目标/确认/续作）、`edl.json`（使用 Video Use 时）、`visual-plan.json`（主帧时序与镜头）、`assets.json`（来源和授权）、`shots/<shot_id>/brief.md`（定制 MG 时）、`verify/`（证据）。有动态导演需求时，在 `project.md` 或独立 `shot-selection.md` 记录内容到候选镜头、MG 取舍与全片节奏，并关联主计划 shot_id；不新增第二套权威时间线。不预填虚构的执行结果。

本 Skill 附带 `scripts/setup_env.py`（环境一键就绪，`--check` 只报告不安装）、`scripts/mg_inspiration.py`（定制 MG 时按用途筛灵感，不整份读索引）和 `scripts/plan_tools.py`：

```text
python plan_tools.py check <edit/visual-plan.json>
python plan_tools.py check <edit/visual-plan.json> --ready
python plan_tools.py export <edit/visual-plan.json> --out <edit/render-manifest.json>
```

命令中的脚本路径相对本 Skill 解析，实际运行使用绝对路径。`export` 只产生标准化交接清单，不渲染、不直接覆盖 EDL；文件已存在会拒绝覆盖。协议见 [时间线契约](references/timeline.md)。

## 当前交付边界

这是可执行的 Agent 工作流 Skill，不是预先写完所有动画的成片软件。附带计划检查与时间换算；每个项目的 Remotion 场景、底片组装、Alpha 解码和音轨混合仍需按已确认镜头实现并试渲染。纯文字方案可先完成；没有实际音频时不承诺词级同步。Workbench 全片编辑、复杂 3D 和具体视频服务自动调用仅在相应接入完成并验证后才宣称可用。
