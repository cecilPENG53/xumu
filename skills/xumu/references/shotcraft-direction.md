# Video Shotcraft：内容选镜头与整片节奏

有运镜、动态揭示或镜头包装需求时，在写动画代码前读本文件。只剪口播、只加字幕或明确不加动画时跳过。用户要 Gallery 效果时，把动作还原和镜头表现列为交付目标。

## 1. 接入方式

从当前会话的同名 Skill、相邻的 `video-shotcraft/` 目录或个人配置解析根目录，完整读取其 SKILL.md。按协作方式读其 `references/pipeline.md`（自主），或 `references/guided-free-creation.md`（共同创作；制作时再读 pipeline）。把它所说的"产品功能"映射为本片的内容段落、证据、演示对象或叙事转折。

序幕总控保持主导：已确认的输入、旁白、风格与协作方式继续有效；Shotcraft 的宣传片模式、Ink Press 皮肤、强鼓点与高能收尾，按本片定位取舍。用户明确要整套模板或独立宣传片时，才进入 Shotcraft 的完整路线。

## 2. 内容到镜头候选

1. 按语义段列出：原文、表达目标、保留人物/证据还是动态呈现、可用素材、shot_id、时间预算。
2. 需要动态的段落：扫描 `references/shots/` 全部卡片 frontmatter（用途、能量、建议时长、限制），可先用 `gallery/api/library.json` 初筛，再回卡片补齐约束。记录索引版本或哈希与扫描范围。
3. 每段比较首选与可行备选：素材条件、动作能否表达内容、时长能否容纳入场与阅读、与前后镜头是否重复、是否符合定位的构图、风格强度与观看尺寸。原片或静态展示可作备选；没有合适候选就如实记录。
4. 阅读入围卡的准确 demo、观看动态样片，按 [MG 六问](directing.md#4-是否定制-mg六问) 决定配方适配、配方加定制图解、纯定制，或取消动画。
5. 用户点名的卡、变体或动作按核心原则 3 处理；名称不明确时按目录核对并用中文解释。已授权自主判断时记录定案，否则随画面方案一并确认。

候选比较的目标是"相关段落经过合理选择"，镜头数量和 Shotcraft 占比不设指标。

## 3. 精确解析与样片

- 核对索引 `cards[].name`、`styles[].key`、`source`、`styles[].media.url`；索引与配方冲突时记录下来并核对源码。
- 按卡片"参考实现"定位 TSX，完整读取选中代码与必要组件。保留关键时值比例、缓动、遮罩时机、路径与已知坑；适配素材、中文、品牌、坐标与构图。
- 动态 MP4 可能不随 Git 下载：先查所选样式的在线 Gallery 地址；需要本地参考时，先读 `gallery/fetch-media.sh` 再决定回收方式，只取本次入围的公开样片。
- 以正常速度观看入围动作，必要时抽入场、峰值、落定、退出帧，记录动作拆解。
- 样片无法访问时标"未验证动态参考"，用准确 demo 做本地短测；用户要求忠实复现时说明差距。
- 标注"仅供参考、需自定义实现"的变体，用户点名时说明风险后使用。只把项目用到的实现复制进项目目录。

## 4. 组织整片

按叙事作用安排动作强弱：建立关注对象 → 展示或解释 → 重点落点 → 留白或回到人物 → 收束。故事、教程、案例、方案可以调整这条弧线。

- **每镜一个主动作**：推近、翻滚、文字揭示错开时间；多个对象有阅读次序，落定后再交给下一个焦点。
- **镜头对比**：全貌与细节、静与动、人物与证据、解释与结果交替；同一手法重复使用时，服务于明确的系列比较或节奏结构。
- **完整动作弧**：准备/入场、变化、语义落点、阅读停留、退场各有时间。沿用配方时值；文字与品牌落定约 1 秒、批量动作后约 0.5 秒作为检查起点。配方要求连续运动时保留，在后续稳定镜头补足阅读。窗口不够时换卡、减少信息，或回头讨论时长。
- **口播先行**：关键变化贴近语义词，原声保持原语速。用户选定音乐主导时才按节拍排。音效与 BGM 按本片意图选用。
- **转场有依据**：章节之间可以较强；同一证据的细节推进保持空间连续。字体、配色、材质与动作强度统一到本片主风格（见 [风格与技术栈](style-stack.md)）。
- **人物回归**：承诺、情绪、解释收束适合回到人物；音频/文案模式用证据或稳定的设计画面承担停留。
- **对比真实性**：擦除用于有对应关系的前后状态；构图不同时用分屏或翻面对照。没有真实网页时，让海报或图像当主角。

完整分镜要看得出每个镜头"为什么在这里"。静态风格确认后，再短测关键动作，然后制作全片。

## 5. 决策记录

在 project.md 或 shot-selection.md 按实际段落填写：

| shot_id / 内容 | 表达目标与素材 | 首选卡·变体 / 主动作 | 备选与取舍 | MG 是否需要及缺口 | 定制灵感 slug（样片已看/未验证） | 风格 · 引擎 | 样片/代码证据与确认状态 |
|---|---|---|---|---|---|---|---|

"定制灵感"列仅在该镜走定制 MG 时填写，来源为 [mg-inspiration-index.json](mg-inspiration-index.json)；不需要定制则留空。

另写一段全片节奏说明：注意点、信息展开、重点与呼吸位、人物/证据切换、转场依据、声音安排。精确帧由 visual-plan.json 派生。

核心运动来自配方时记 `route=shotcraft`，并填写真实的 `card/style_key`；混合镜头说明原创部分。候选选择、名称真实性、动作还原与节奏由导演自检和独立审查核对（plan_tools 只校验结构）。交付时简述实际用到的配方、定制 MG，以及未采用的用户指定动作及原因。
