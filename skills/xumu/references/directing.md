# 内容到画面：先判断表达，再选路线

## 1. 叙事判断

承接 [制作定位](production-profile.md)，把受众、目的、风格与时长落到每个段落的目标上；章节长片先组织论述，再选局部画面。

逐段写清观众要理解的对象、关系或情绪，把主信息、例子、证据、情绪、过渡分开。画面的价值在于帮助理解；字幕已经说清的句子不必再做一遍动画。动画跟着内容需要出现，不按固定间隔插入。

优先保留可信的人物表达、具体成果、真实操作与高质量原素材。剪接与动作只呈现原文已有的因果关系。视觉隐喻和故事再现记录映射关系，并标为示意。

## 2. 路线选择

| 内容需要 | 推荐起点 | 常见误用 |
|---|---|---|
| 观点、情绪、承诺 | 人物镜头，或克制的背景与大字排版 | 关键词一出现就加特效 |
| 真实操作、真实成果 | 真实录屏、截图、成品，配 Shotcraft 推近、聚焦、陈列 | 用合成界面代替真实操作 |
| 顺序、循环、汇聚、分支、对比 | 先看静态图或原片能否讲清；需要动态时比较机制配方，再定适配或定制 MG | 所有机制都画成同一种三节点循环 |
| 指标变化 | 有来源的数据驱动图表 | 装饰性数字 |
| 人物故事、空间情境 | 插画分层与姿态；人物抠像进场景；必要时外部视频 | 用卡片移动代替角色表演 |
| 年代感、氛围、情绪转场 | 风格化绘制（像素、手绘、胶片质感），见 [风格与技术栈](style-stack.md) | 风格与内容无关地堆叠 |
| 三维结构、产品转台 | Three.js 代码几何，或用户提供的 3D 模型 | 把生成视频当成可编辑模型 |
| 公式、算法、物理原理 | Manim 或 SVG 精确图解 | 用装饰动画代替推导 |

句子级的画面组织（定义、对比、步骤、数据、引用……该怎么画）见 [解说语法](explainer-grammar.md)。

用户说辅助画面不够时，先逐段找出口播讲到了对象、操作、变化或结果却没有画面帮助的地方，再补对应的素材或图解；不按时长比例堆装饰镜头，也不让字幕、标题、卡片重复同一句话。

路线可以混用，全片保持统一的字体、色板、图形语言与叙事空间。口播 IP 以用户品牌为主；展示真实产品时保留其识别特征。中文行宽、字体文件、竖屏人物区与字幕区在风格确认时一起检查。

## 3. 可视化设计步骤

1. **一句话目标**：例如"让观众看懂三条输入如何经过分类分发"。
2. **实体与关系**：来源、规则、结果分别是什么；哪些元素保持身份；哪些是真实数据。
3. **阅读顺序**：先对象，再变化，再结果；关键落点跟着语义词出现，元素依次登场。
4. **素材清单**：真实截图、SVG、分层角色、姿态、背景、视频片段或三维模型；尚不存在的标"待制作"。
5. **风格与技术**：按 [解说语法](explainer-grammar.md) 找画面组织与现成组件，按 [风格与技术栈](style-stack.md) 选绘制技术与引擎，与全片主风格一致。
6. **镜头比较与 MG 判断**：按 [Shotcraft 选镜头](shotcraft-direction.md) 比较候选，再回答下面的六问。
7. **节奏与分镜**：按旁白长度、信息量与动作可读性分配停留。长图解放不进短窗口时，换镜头或拆分信息量，原声长度保持不变。

## 4. 是否定制 MG：六问

1. **静止是否更清楚？** 人物情绪、可信表达、短结论、细密证据可以直接保留或静止阅读。
2. **是引导视线，还是解释机制？** 展示作品、从全貌到细节、章节切换、引出重点，先用 Shotcraft 的运动、揭示与转场。
3. **配方能否准确表达关系？** 只需换素材、中文、色板、布局、实体数量且保留动作语法时，属于配方适配。中文内容和真实图片都可以适配。
4. **缺口究竟是什么？** 独有因果链、随真实数据变化的图表、算法或流程规则、空间结构、行业专属示意，现有配方表达不了时定制；写明关系与所比较配方的不足。
5. **能否混合？** 例如自绘流程节点解释机制，外层用配方运镜聚焦；标清借用的运动与原创的图解，同一时刻只有一个主动作。
6. **定制怎么写？** 查找顺序固定：Shotcraft 镜头卡 → [解说语法](explainer-grammar.md) 与本地动效参考（`motion_index.py`）→（仅当用户点名的效果在前两者中没有时）HyperFrames 效果库搜一次，见 [后端发现](backends.md#hyperframes-按需接入) → 灵感索引与从零定制。不对每个段落都走遍所有来源。第 4 问的缺口成立后，读 [mg-prompt-patterns.md](mg-prompt-patterns.md)：按段落用途从 mg-inspiration-index.json 入围 2–4 条并看样片，选一个形式概念，写本镜 brief（锁定文案、视觉规范、分镜、动作规则、禁用清单、自检）。灵感条目多为无旁白炫技片，按该文件第 2 节翻译成口播节奏和本片风格强度。

`route` 记录设计来源（shotcraft、mg、illustration……），`engine` 记录渲染引擎，`style` 记录画面语言，三者相互独立。素材属性记在 assets.json。混合镜头按主要来源记 route，必要时拆成有意义的多个 shot_id。

## 5. 给用户确认的画面方案

**选择表**：内容摘句 | 表达目的 | 首选镜头与动作 | 备选或不动 | 是否定制 MG 及理由 | 风格与技术 | 手法卡。用中文描述效果，卡名附在后面；没有合适备选时说明原因。

**完整分镜**：剪后时间段/shot_id | 画面与主动作 | 素材来源 | 入场 → 落点 → 停留 → 退出 | 字幕、转场、声音。说明开场、信息展开、重点镜头与收尾如何衔接；外部生成费用单独列出。精确帧数以 visual-plan.json 为准。

**风格确认**：用代表帧验证品牌、中文排版与构图，用短测验证运动手法，确认后再批量制作。用户点名的风格或镜头作为约束；未点名时给出推荐理由，用效果描述代替卡片术语。风格名称（如"杂志排版""深色科技"）先落成主视觉、文字层级、人物比例、色彩、辅助画面类型与动作强度，再出代表帧，不直接套现成的标题卡和字幕条。

**参考图**：先写出看得到的构图：主体与辅助画面的大小关系、观看顺序、标题与引导元素（箭头、编号）的作用，再决定继承哪些。用户点名要参考的排版按原样继承（核心原则 3）。圈注、红框、手写标记多半是用户的说明，判断后再决定是否入画。静态截图看不出动作节奏，动态部分记为"参考未提供"，不说已复刻。

## 6. 原声与文字分工

- `quote`：实际口播原文，用于追溯。
- `screen_text`：在不改变原意的前提下提炼，只用已核实的信息。
- 字幕：逐字对应实际声轨。
- 画面需要改变旁白才能成立时，回到剪辑策略重新确认。
